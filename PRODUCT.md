# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The primary visitors are recruiters and hiring managers who need to understand Rushil's current role and technical focus quickly. Engineers should find enough concrete detail to judge the work, and design-aware peers should notice the craft without the interface getting in the way.

## Product Purpose

This is Rushil Choksi's personal website. It introduces who he is now, the kinds of infrastructure and security problems he works on, a deliberately small set of work worth exploring, and his writing and projects beyond his day job.

Success means a first-time visitor can identify Rushil, his current position, and his engineering focus within seconds, then move into credible project, experience, or writing detail without encountering inflated claims.

## Positioning

Rushil is a software security engineer whose work spans infrastructure, security, systems, software engineering, and AI. The site should show that range through selected real work rather than through a generic capability list or a conventional resume presentation.

## Operating Context

The site is a public, crawlable portfolio hosted from this repository and intended to work across small phones, tablets, laptops, and large desktop displays. It must preserve ordinary browser behavior, keyboard use, text selection, and direct external links.

## Capabilities and Constraints

- Rushil's current role is Software Security Engineer at Aurelian, with significant infrastructure and security focus.
- Rushil completed an MS in Cyber Security Engineering at USC.
- Rushil is based in Seattle, Washington.
- The repository contains older public projects, four external articles, historical biography copy, personal photographs, and an abandoned space-themed redesign experiment.
- Confidential or private work must remain high-level. Missing outcomes, dates, architecture details, and metrics must not be invented.
- Personal, project, work, and writing content must be centralized so future updates do not require presentation-component edits.
- The site must meet WCAG 2.2 AA as a baseline, honor reduced-motion preferences, remain usable without hover or animation, and target strong Core Web Vitals.

## Brand Commitments

- The subject name is Rushil Choksi and it must be unmistakable in the first viewport.
- Voice is concise, technically literate, human, and direct. It avoids buzzwords, corporate polish, self-congratulation, and generic calls to action.
- The requested identity is quiet technical luxury, editorial design, and systems engineering. It must imply engineering sophistication without cybersecurity cliches.
- The visual system uses disciplined typography, off-black and off-white surfaces, one restrained accent, very few containers, and one subtle recurring trace or routing motif.
- The experience must not resemble a hacker terminal, cybersecurity theme, SaaS landing page, resume template, dashboard, component-library demo, or generic developer portfolio.

## Evidence on Hand

- The explicit brief confirms the current Aurelian role and completed USC graduate degree.
- The tracked historical site contains public descriptions and repository links for Space Launch Window Detection, Secure Authentication Architecture, RNN Password Generator, Solar Splash, Secure FTP, a private URL shortener, and private RPA work.
- The tracked historical site contains external links to four published articles: quantum-era data security, fileless malware, financial transaction monitoring, and security monitoring with UEBA.
- The repository contains three personal photographs and legacy project/article imagery. Several project and article images are generic or stock-like and should not be treated as proof of project outcomes.
- GitHub, LinkedIn, Medium, Stack Overflow, and HackerRank profile links exist in the historical site. GitHub, LinkedIn, and Medium are the most relevant primary profiles.
- No current resume file, current professional case-study material, testimonial, award documentation, or verified performance metric is present in the tracked historical site. Future work must not fabricate these.

## Product Principles

1. Lead with the person and the current work, not a theme.
2. Prefer a few credible artifacts over an exhaustive project archive.
3. Let typography, composition, and interaction detail carry the identity.
4. Make every claim traceable to the brief or repository evidence.
5. Preserve fast, accessible, ordinary web behavior beneath the craft.

## Accessibility & Inclusion

WCAG 2.2 AA is the baseline. The interface requires visible focus states, logical landmarks and heading order, sufficient contrast, appropriate target sizes, reduced-motion support, keyboard-complete interaction, and touch alternatives for pointer enhancements.
